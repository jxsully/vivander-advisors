What is an agent-ready website?

Michael J. Goldrich · September 2026

An agent-ready website is one an AI agent can read and act on without a human interpreting the screen. The facts sit in the initial HTML. Interactive elements are native controls with labels. The accessibility tree reads in order. Its primary action is visible and uncovered. And a booking or reservation can be completed without a phone call. At Vivander Advisors I report agent readiness and agent perception as scores beside the visibility score in every hospitality audit, never inside it, because they decide whether a recommendation converts rather than whether it occurs. The same investment serves four audiences at once: people using assistive technology, search crawlers, answer engines selecting fragments, and agents acting on a customer's behalf.

I asked my personal AI agent to find me a hotel near Bryant Park. It found one. Then it kept shopping. That is the customer your website is about to meet.

How do agents read a website?

Three ways at once, and they cross-reference. Google's Chrome team: agents use the DOM and accessibility tree to get a clean structured list of interactive elements, then cross-reference with a visual rendering to understand layout. OpenAI: ChatGPT Atlas uses ARIA tags, the same labels and roles that support screen readers. Playwright, the framework most agents run on, serializes the accessibility tree.

The industry is converging on the accessibility tree. It is the smallest representation that carries what an agent needs, and it is the same structure screen readers have used for twenty years.

What breaks an agent?

A UC Berkeley and Michigan study for CHI 2026 tested an agent on 60 real web tasks. Standard conditions: 78 percent success. Keyboard-only: 42 percent. Magnified viewport: 28 percent. Three failure modes: perception gaps, cognitive gaps, action gaps. Visual-only cues, hover states and JavaScript reveals create all three.

Two failures pass every accessibility audit and stop an agent, per Google's own guidance. A journey-critical element under 8 square pixels risks being filtered out by visual analysis. And a node covered by another layer, even a transparent one, may be discarded. Consent-banner residue over the book-now button is the case to check first.

What does the checklist look like?

Facts in the initial HTML: rate, room types, menu, hours, policies, capacity. Native buttons and links, no div click handlers. Every input labeled, with autocomplete attributes. Landmark regions declared. Descriptive headings, not "Learn More." The same action in the same place across a template family. A pointer cursor on everything actionable. The primary action larger than 8 square pixels and uncovered after every banner closes, confirmed by hit-testing its center. A booking path that returns a real rate and availability to a direct request.

What about llms.txt, WebMCP and the rest?

llms.txt has no effect on visibility, per Google, and a narrow life as an agent-context file for sites that expose developer tools. WebMCP is a community draft, off by default in Chrome, an early-mover signal for interaction and not a traffic driver. Web Bot Auth is production-active with no ratified standard. Markdown content negotiation is cheap and genuinely early-mover. None of them substitute for the checklist above. Google Cloud's Open Knowledge Format, published in June 2026, is about internal company knowledge, and it points at the same direction: write things down so agents can read them without a custom setup for every source.

How does Vivander test it?

A no-JavaScript fetch of every key page. Then a rendered-DOM read after scripts run. A Playwright accessibility snapshot, which shows exactly what Atlas and Comet read. Screenshots at documented desktop and mobile viewports with element geometry for hit area. And a walk of the booking path to the last screen before commitment, every dead end recorded. Cloudflare's isitagentready.com scanner runs on the Content Site preset, per-check detail read, composite ignored.

Where this is going

The agent reads protocols, not pretty homepages. It reads structured signals, real-time availability, machine-readable trust. If your data is not ready for that conversation, you are not in the conversation.

Your homepage was designed for people who arrived curious. Agents deliver people who arrived certain. Those are different visitors, and they need a different first screen.
